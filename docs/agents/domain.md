# Domain docs

This repo uses a single-context layout. Before working in an area, read the
root `GLOSSARY.md` and relevant architecture decision records in `docs/adr/`
when they exist. If either is absent, continue with the available docs.

Use glossary terms in issues, proposals, code, and tests. If an established
project concept is missing, flag it for `/domain-modeling`. Create glossary
entries and decision records as terminology and decisions are settled.

If a proposal conflicts with an existing decision, cite the ADR and explain
why the decision merits reconsideration.
